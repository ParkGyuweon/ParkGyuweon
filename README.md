#### [01] [화분 HWABUN — 소규모 뷰티 브랜드를 위한 공유 데이터 인프라 · 추천 플랫폼](https://github.com/ParkGyuweon/hwabun)

> SSAFY 2학기 특화 프로젝트 (2026.08 – 2026.10) · **최종 발표회 서울 3반 1위** · 6인 팀, 담당: **AI · 추천 / 데이터 시뮬레이션**

여러 소규모 브랜드가 하나의 분석 인프라를 함께 쓰는 통합 뷰티 쇼핑몰입니다. 소비자 행동을 43종 이벤트로 수집해 Kafka와 Spark로 마트·DW에 쌓고, 소비자에게는 개인화 추천으로, 브랜드에는 인사이트 대시보드로 돌려줍니다.

`행동 로그 43종` → `Kafka (파티션 3)` → `Spark Q1–Q5 (마트 25종 · 품질 검사 171개)` → `DW (MySQL)` → `대시보드 / 추천`

**담당 역할**
- 추천 모델과 쇼핑몰 백엔드가 프록시하는 실시간 FastAPI 추천 서버(라우트 24개) 구현
- 파이프라인 전체를 검증할 트래픽 제작: 페르소나 기반 행동 로그 생성기와 LLM 브라우저 에이전트
- 상품 피처 계약·어휘집·등록 흐름을 맡아, 새로 등록한 상품이 바로 추천 후보에 들어가도록 구성

**데이터 흐름 · 시뮬레이션**
- 실제 Sephora 리뷰 84만 건에서 만든 **페르소나 9,900명**으로 **행동 로그 약 1,049만 건** 생성. 프론트 로거와 같은 이벤트 봉투를 써서 하류에서는 모든 트래픽이 한 스키마로 흐름
- Playwright + GPT로 실제 브라우저에서 쇼핑몰을 조작하는 **LLM 에이전트 100명**을 돌려, 운영 프론트 로거를 처음부터 끝까지 검증
- Kafka `activity-events` 토픽을 별도 컨슈머 그룹으로 구독해 세션 상태를 실시간 갱신. 로그 파싱 병목을 찾아 제거(로컬 기준 초당 1,000 → 35,000 이벤트)
- DW `user_trait_daily` 테이블을 읽어 추천 응답에 장기 성향을 반영
- Spark 품질 검증(Q5) 위반을 마트 grain(상품 · 날짜 · items 펼침 · 시드 행)을 맞춰 출처까지 추적하고, 생성기 쪽 근본 원인을 수정
- 배포 환경 부하 테스트: 목표 2,000 TPS 대비 **초당 16,000 이벤트를 10분간 지속, 거절 0건**

**추천 · 평가**
- 멀티핫 블록 8종 + 스칼라로 된 148차원 상품 벡터, 블록 가중치는 문서 빈도로 계산
- 콘텐츠 유사도, 페르소나 속성 친화도, 상품 동시발생 CF를 **LTR(Learning-to-Rank)** 로 결합 (HistGradientBoosting, 피처 20개, 학습 383,967행). 학습과 서빙이 같은 피처 모듈 사용
- 실제 구매 이력 위에 **홀드아웃 3세트(10,400명)** 오프라인 평가 체계를 설계. 한 세트에서 고르고 다른 세트에서 확인해 단일 테스트셋 과적합을 피함
- **Recall@10 23.4% (CBF) → 38.2% (+CF) → 43.8% (LTR)**, 인기순 기준선(10.8%)의 약 4배
